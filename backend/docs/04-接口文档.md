## 1 通用约定

### 1.1 访问入口

| 场景 | 地址 | 说明 |
| --- | --- | --- |
| 联调/生产统一入口 | `http://localhost`(Nginx :80) | 所有 `/api/**` 由 Nginx 轮询转发至 backend-app-1/2 |
| 后端单实例调试 | `http://localhost:8080`、`http://localhost:8081` | 绕过 Nginx, 直接定位单实例问题 |

统一前缀: `/api`。

### 1.2 统一响应信封

所有接口(含错误)一律返回:

```json
{ "code": 0, "msg": "ok", "data": {} }
```

- `code = 0` 表示成功, 非 0 为失败, `msg` 为人类可读信息;
- 分页接口 `data` 固定为: `{ "total": 总数, "page": 当前页, "size": 每页条数, "list": [ ... ] }`;
- 前端**不要**根据 HTTP 状态码判断业务状态, 一律以 `code` 为准。

### 1.3 错误码表

| code | HTTP 状态 | 含义 | 前端处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | — |
| 401 | 401 | 未登录 / Token 过期或无效 | 清除本地 token, 跳转登录页 |
| 403 | 403 | 无权限访问 | 提示"无权限" |
| 404 | 404 | 资源不存在 | 提示"数据不存在或已被删除" |
| 409 | 409 | 数据冲突(重复编号、存在关联数据等) | 展示 `msg` 即可 |
| 422 | 422 | 参数校验失败(`msg` 含具体字段) | 展示 `msg`, 标红对应表单项 |
| 429 | 429 | 触发限流(检索接口 10r/s) | 提示"操作过于频繁, 请稍后再试" |
| 500 | 500 | 服务器内部错误 | 提示"服务器开小差了", 通知后端查日志 |

### 1.4 认证方式

- 登录接口 `POST /api/auth/login` 返回 JWT;
- 之后所有受保护接口携带请求头: `Authorization: Bearer <token>`;
- 免鉴权白名单(其余全部鉴权): `POST /api/auth/login`、`GET /api/health`;
- 后端双实例无状态, **业务代码禁止使用 HttpSession 存用户信息**(JWT 无状态才支持轮询负载均衡)。

### 1.5 数据类型约定

| 约定项 | 规则 |
| --- | --- |
| 时间 | ISO 8601 带时区字符串, 如 `2026-09-11T10:30:05+08:00`(前端负责格式化显示) |
| 分页 | `page` 从 1 起, `size` 默认 20, 最大 100 |
| 字段命名 | JSON 一律 camelCase |
| deviceType | `UAV`(无人机) / `ROBOT_DOG`(机器狗) |
| device.status | `ONLINE` / `OFFLINE` |
| task.status | `CREATED` / `DISPATCHED` / `RUNNING` / `FINISHED` / `FAILED` |
| task.taskType | `THERMAL`(红外测温) / `IMAGE`(航拍巡检) / `SENSOR`(环境监测) / `COMPREHENSIVE`(综合) |
| alarm.level | `CRITICAL` / `MAJOR` / `MINOR` |
| alarm.status | `NEW` / `PROCESSED` |
| 经纬度 | 对外统一 `{ "lng": 116.397, "lat": 39.908 }`; ES 内部 `geo_point` 需 `{lat, lon}` 格式, **由后端转换**, 前端无需关心 |
| 金额/数值 | 直接数字, 不使用千分位字符串 |

## 2 接口明细(共 19 个)

### 2.1 认证与健康

#### 2.1.1 POST /api/auth/login —— 登录

| 项 | 内容 |
| --- | --- |
| 权限 | 免鉴权 |
| 请求体 | `{ "username": "admin", "password": "admin123" }` |

请求字段:

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 登录账号 |
| password | string | 是 | 密码(明文传输, 生产需 HTTPS) |

成功响应(200):

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9....",
    "expiresIn": 7200,
    "user": { "username": "admin", "realName": "巡检管理员", "role": "ADMIN" }
  }
}
```

失败响应(401):

```json
{ "code": 401, "msg": "用户名或密码错误", "data": null }
```

> 说明: `expiresIn` 单位秒(默认 2 小时); 开发期内置账号 `admin/admin123`, 接入 Mongo 用户表后以实际用户为准。

#### 2.2.2 POST /api/devices —— 新增设备

| 项 | 内容 |
| --- | --- |
| 请求体 | `{ "deviceId": "UAV-002", "deviceType": "UAV", "name": "无人机2号", "model": "巡检无人机-M300", "area": "1号变电站·东区", "position": { "lng": 116.401, "lat": 39.910 } }` |

请求字段:

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| deviceId | string | 否 | 不传则后端生成; 传入必须唯一 |
| deviceType | string | 是 | `UAV` / `ROBOT_DOG` |
| name | string | 是 | 设备名称 |
| model | string | 否 | 型号 |

#### 2.2.3 PUT /api/devices/{id} —— 更新设备

| 项 | 内容 |
| --- | --- |
| 请求体 | `{ "name": "无人机1号(改)", "area": "2号变电站·西区", "position": { "lng": 116.41, "lat": 39.92 } }` |

- 可更新字段: `name` / `model` / `area` / `position` / `faultCode`; **不可更新**: `deviceId`、`deviceType`、`status`(状态由心跳驱动);
- 未传字段保持不变(部分更新)。

失败场景: 404 —— 设备不存在; 422 —— 校验失败。

#### 2.2.4 DELETE /api/devices/{id} —— 删除设备

- 无请求体; 成功: `data: null`, `msg: "ok"`;
- 失败场景: 404 —— 设备不存在; **409 —— 该设备存在未完成任务**(`task.status` 为 CREATED/DISPATCHED/RUNNING), 拒绝删除。

#### 2.2.5 GET /api/devices/{id} —— 设备详情

成功响应: `data` 为完整 device 对象(含 `lastHeartbeat`, 前端可据此计算"最后在线时间")。

失败场景: 404 —— 设备不存在。

> 设备离线检测(TC-010): 后端定时扫描 `lastHeartbeat` 超过 15s(3 个心跳周期)未更新的设备置 `OFFLINE` 并产生离线告警, 前端可轮询本接口或 `/api/devices?status=ONLINE` 感知状态变化。

### 2.3 任务管理

巡检任务对象(patrol_task)字段:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| taskId | string | 任务编号(PK), 后端生成如 `T-003` |
| name | string | 任务名称 |
| taskType | string | `THERMAL`/`IMAGE`/`SENSOR`/`COMPREHENSIVE` |
| area | string | 巡检区域 |
| deviceIds | string[] | 指派设备编号数组(非空) |
| status | string | `CREATED`/`DISPATCHED`/`RUNNING`/`FINISHED`/`FAILED` |
| createTime | string | 创建时间 |
| dispatchTime | string | 下发时间(发 Kafka 指令成功即 `DISPATCHED`) |
| finishTime | string | 完成时间(未完成 null) |
| result | object | 执行结果摘要, 未完成 null: `{ "pointCount": 12, "alarmCount": 1, "detail": "测温点位12个,采集完成" }` |

#### 2.3.1 POST /api/tasks —— 创建并下发巡检任务

请求体:

```json
{
  "name": "2号主变压器红外测温",
  "taskType": "THERMAL",
  "area": "1号变电站·东区",
  "deviceIds": ["ROBOTDOG-002"],
  "params": { "points": 12, "tempThreshold": 80 }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 任务名称 |
| taskType | string | 是 | 枚举值见上 |
| area | string | 否 | 巡检区域 |
| deviceIds | string[] | 是 | 非空数组; 全部设备必须存在且为 ONLINE, 否则 409 |
| params | object | 否 | 指令参数, 随 TASK_COMMAND 原样下发(格式见附录 A.2); 缺省时后端按 taskType 取默认值(THERMAL: `points=12`、`tempThreshold=80`) |

成功响应(200): `data` 为完整任务对象(`status=DISPATCHED`, 下发为同步动作; `CREATED` 仅为其间的瞬时态, 对外不可见)。

后端行为: 写 Mongo → 发 Kafka `patrol.task.command` 指令 → `dispatchTime` 记录, `status=DISPATCHED` → 仿真器回 `patrol.task.result` 后更新状态。

失败场景: 409 —— `deviceIds` 中存在不存在或 OFFLINE 设备(`msg` 列出问题设备); 422 —— 校验失败。

#### 2.3.2 GET /api/tasks —— 任务分页查询

查询参数: `status`(否)、`type`(否)、`page`(否)、`size`(否); 按 `createTime` 倒序。

成功响应: `data` 为标准分页信封, `list` 为任务对象数组(不含 `result` 明细, 仅含 `result.pointCount/alarmCount` 摘要)。

#### 2.3.3 GET /api/tasks/{id} —— 任务详情与执行进度

成功响应:

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "task": { "taskId": "T-002", "name": "...", "...": "..." },
    "deviceProgress": [
      { "deviceId": "ROBOTDOG-002", "status": "RUNNING", "progress": 60, "lastUpdateTime": "2026-09-11T10:20:00+08:00" }
    ]
  }
}
```

`deviceProgress[].progress` 为 0-100 整数, 由后端估算: THERMAL 任务 = 该设备已上报测点数 / 指令 `params.points`; 其他类型任务按已上报消息量与指令目标量之比估算(见附录 A.2 TASK_COMMAND)。

失败场景: 404 —— 任务不存在。

### 2.5 检索分析

#### 2.5.1 POST /api/search/events —— 巡检事件检索

> 该接口经 Nginx 限流(每 IP 10r/s, 突发 20), 触发 429 时前端应提示稍后再试, **禁止**前端自动无限重试。

请求体:

```json
{
  "deviceId": "ROBOTDOG-002",
  "eventTypes": ["THERMAL", "ALARM"],
  "alarmLevel": "CRITICAL",
  "area": "1号变电站",
  "from": "2026-09-11T00:00:00+08:00",
  "to": "2026-09-14T23:59:59+08:00",
  "keyword": "变压器 高温",
  "geo": { "center": { "lng": 116.397, "lat": 39.908 }, "radiusKm": 5 },
  "page": 1,
  "size": 20
}
```

请求字段:

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| deviceId | string | 否 | 设备精确匹配 |
| eventTypes | string[] | 否 | `IMAGE`/`THERMAL`/`SENSOR`/`ALARM` 多选 |
| alarmType | string | 否 | 告警类型精确匹配 |
| alarmLevel | string | 否 | 告警级别 |
| area | string | 否 | 区域 keyword 匹配 |
| from / to | string | 否 | 时间范围(ISO 8601), 缺省最近 24h |
| keyword | string | 否 | 对 description 全文检索(ik 分词) |
| geo | object | 否 | `{center:{lng,lat}, radiusKm}` 半径检索; 与 bbox 二选一 |
| bbox | object | 否 | `{topLeft:{lng,lat}, bottomRight:{lng,lat}}` 矩形检索; 与 geo 二选一 |
| page / size | int | 否 | 分页 |

成功响应: 标准分页信封, `list` 为事件对象数组:

```json
{
  "eventId": "E-20260911-001",
  "deviceId": "ROBOTDOG-002",
  "deviceType": "ROBOT_DOG",
  "deviceName": "机器狗2号",
  "eventType": "ALARM",
  "alarmType": "TEMP_OVER",
  "alarmLevel": "CRITICAL",
  "taskId": "T-002",
  "area": "1号变电站·东区",
  "temperature": 92.3,
  "threshold": 80.0,
  "position": { "lng": 116.398, "lat": 39.909 },
  "eventTime": "2026-09-11T10:32:00+08:00",
  "description": "2号主变压器热点温度92.3℃,超过严重阈值80℃"
}
```

失败场景: 422 —— geo 与 bbox 同时传 / 参数非法。

### 2.6 报告服务

    "alarmTypeDist": [ { "key": "TEMP_OVER", "count": 3 } ],
    "deviceRank": [ { "deviceId": "ROBOTDOG-002", "count": 34 } ]

失败场景: 422 —— 时间范围非法。

### 2.7 文件上传下载

hdfs_file 对象字段:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| fileId | string | 文件编号(PK), 后端生成 `img-xxxxxxxx` |
| fileName | string | 原始文件名 |
| hdfsPath | string | HDFS 路径, 如 `/patrol/1号变电站/2026-09-11/UAV-001/img-xxx.jpg` |
| deviceId | string | 来源设备(可为 null) |
| taskId | string | 关联任务(可为 null) |
| fileSize | long | 字节数 |
| uploadTime | string | 上传时间 |

#### 2.7.1 POST /api/files —— 上传巡检图片

| 项 | 内容 |
| --- | --- |
| Content-Type | `multipart/form-data` |
| 表单字段 | `file`(文件, 必填)、`deviceId`(可选)、`taskId`(可选) |
| 限制 | 仅图片 `jpg/jpeg/png/webp`, 单文件 ≤ 20MB(Nginx 与后端双重限制) |

成功响应:

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "fileId": "img-3f2a9c1b",
    "fileName": "UAV-001_20260911_103000.jpg",
    "hdfsPath": "/patrol/1号变电站/2026-09-11/UAV-001/img-3f2a9c1b.jpg",
    "fileSize": 204800,
    "uploadTime": "2026-09-11T10:30:00+08:00"
  }
}
```

后端行为: 图片流经 WebHDFS 写入 HDFS(按 `区域/日期/设备` 三级目录归档) → Mongo 登记 `hdfs_file` 元数据。

失败场景: 422 —— 非图片类型/超过 20MB/文件为空; 500 —— HDFS 写入失败(msg 含原因)。

#### 2.7.2 GET /api/files —— 文件元信息查询列表

查询参数: `deviceId`(否)、`taskId`(否)、`page`(否)、`size`(否); 按 `uploadTime` 倒序。

成功响应: 标准分页信封, `list` 为 hdfs_file 对象数组。

#### 2.7.3 GET /api/files/{fileId}/download —— 影像文件下载

- 受保护接口(需 JWT); 前端用 axios/fetch 携带 `Authorization` 请求头获取 blob;
- 成功响应: 图片二进制流, `Content-Type: image/*`, `Content-Disposition: inline; filename="..."`;
- 失败: 404 —— 文件不存在(HDFS 或 Mongo 任一缺失均视为 404)。

## 附录 A Kafka 消息契约(已对齐《需求分析文档》v1.0 §6.1/§6.2)

### A.1 消息信封(所有上报 Topic 统一, 与需求文档 §6.1 一致)

```json
{
  "msgId": "9a3b2c1d-0000-4000-8000-000000000001",
  "msgType": "IMAGE | THERMAL | SENSOR | STATUS | HEARTBEAT | TASK_RESULT | REGISTER | TASK_COMMAND",
  "deviceId": "UAV-001",
  "deviceType": "UAV",
  "timestamp": "2026-09-11T10:30:00+08:00",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| msgId | string | UUID, 消费端幂等去重依据(架构 §5) |
| msgType | string | 消息类型, 与 Topic 一一对应, 见 A.2 |
| deviceId | string | 设备编号; 分区键(架构 §5 按 deviceId 分区保序) |
| deviceType | string | `UAV` / `ROBOT_DOG` |
| timestamp | string | 设备侧产生时间(ISO 8601) |
| data | object | 各 msgType 业务载荷, **字段与需求文档 §6.2 完全一致**, 见 A.2 |

> 注意: 信封**没有** taskId 字段 —— 与任务相关的信息(taskId)一律放在 `data` 载荷内(见 A.2 各载荷)。

### A.2 各消息类型 data 载荷(与需求文档 §6.2 一致)

| Topic | msgType | data 载荷字段 | 说明 |
| --- | --- | --- | --- |
| patrol.device.register | REGISTER | `{ "name": "无人机1号", "model": "巡检无人机-M300", "area": "1号变电站·东区", "lng": ..., "lat": ... }` | 已定案(v1.2); 后端收到即创建设备记录(初始 `status=OFFLINE`、`battery=100`), 首条心跳置 ONLINE |
| patrol.device.heartbeat | HEARTBEAT | `{ "battery": 86 }` | 5s 周期; 离线检测依据消息到达时间 |
| patrol.device.status | STATUS | `{ "online": true, "battery": 87, "faultCode": "", "mode": "PATROL" }` | 电量/故障变化时立即上报 |
| patrol.drone.image | IMAGE | `{ "imageId": "img-xxx", "cameraType": "VISIBLE\|INFRARED", "lng": ..., "lat": ..., "altitude": 120.5, "taskId": "T-001", "fileName": "UAV-001_xxx.jpg", "fileSize": 204800, "imageBase64": "..." }` | 已定案(v1.2): `imageBase64` 为**可选**字段(模拟图片 ≤200KB, 有值则后端解码写 HDFS + 登记 Mongo); 仅发元数据时省略。手工上传仍走 POST /api/files |
| patrol.dog.thermal | THERMAL | `{ "pointId": "TMP-001", "targetDevice": "2号主变压器", "temperature": 92.3, "ambientTemp": 31.2, "lng": ..., "lat": ..., "taskId": "T-002" }` | **每条消息一个测点**; 后端聚合统计点位数量 |
| patrol.dog.sensor | SENSOR | `{ "temperature": 33.1, "humidity": 62.0, "gas": 0.02, "lng": ..., "lat": ... }` | 环境传感器 |
| patrol.task.result | TASK_RESULT | `{ "taskId": "T-002", "status": "FINISHED\|FAILED", "detail": "测温点位 12 个,采集完成", "finishTime": "2026-09-11T10:45:00+08:00" }` | 后端据此更新任务状态; pointCount/alarmCount 由后端从消费数据中统计 |
| patrol.task.command | TASK_COMMAND | `{ "taskId": "T-002", "taskType": "THERMAL", "area": "1号变电站·东区", "deviceIds": ["ROBOTDOG-002"], "params": { "points": 12, "tempThreshold": 80 } }` | 已定案(v1.2): 沿用同一信封, `deviceId` 为目标设备; `params.points` 为计划测点数(进度估算依据), `params.tempThreshold` 为超温告警阈值(仅 THERMAL 任务携带) |

### A.3 需求空白定案记录(v1.2, 2026-09-15)

1. **IMAGE 图片二进制怎么传?** 需求文档 FR1-4 要求"图片二进制数据/模拟图片", 但 §6.2 的 IMAGE 载荷只有元数据。
   **定案**: `data` 增加可选字段 `imageBase64`(模拟图片 ≤200KB, base64 后 <300KB, Kafka 默认单条 1MB 上限安全), 后端解码写 HDFS + 登记 Mongo; 同时保留 POST /api/files 接口供前端手工上传。仅发元数据时省略该字段。
2. **REGISTER 载荷**: **定案**为 `{name, model, area, lng, lat}`(deviceId/deviceType 已在信封); 后端收到即创建设备记录, 初始 `status=OFFLINE`、`battery=100`, 首条心跳置 ONLINE。
3. **TASK_COMMAND 格式**: **定案**为沿用同一信封结构, `deviceId` 为目标设备, msgType 取 `TASK_COMMAND`; `params` 定为 `{points, tempThreshold}` —— `tempThreshold` 同时解决超温告警阈值来源问题(仅 THERMAL 任务携带), POST /api/tasks 可选传 `params`, 缺省取 §2.3.1 默认值。

## 附录 C 前端联调约定

**1. 开发期代理(与生产路径一致, 不产生跨域)** —— `vite.config.ts`:

```ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      '/api': { target: 'http://localhost:80', changeOrigin: true }
    }
  }
})
```

**2. axios 封装约定**: 统一请求拦截器加 `Authorization` 头; 统一响应拦截器——`code !== 0` 时按 §1.3 处理, **401 时清除 token 并跳转登录页**; 429 提示"操作过于频繁"。

**3. 实时性约定**: 本版本暂不做 WebSocket/SSE, 状态大屏用轮询(设备列表 5s 一次, 建议只查 `?status=ONLINE`); 后续扩展 SSE 不影响现有接口。

**4. 轮询负载均衡前提**: 后端双实例无状态(JWT), 前端**不要**依赖任何"同一个实例"的假设; 调试时用 `GET /api/health` 的 `instance` 字段确认命中哪个实例。

**5. 每日冒烟脚本(联调前跑一遍)**:

```bash
# 登录拿 token
TOKEN=$(curl -s -X POST http://localhost/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 健康检查 × 6(观察 instance 轮询交替)
for i in $(seq 1 6); do curl -s http://localhost/api/health | python -c "import sys,json;print(json.load(sys.stdin)['data']['instance'])"; done

# 设备列表
curl -s http://localhost/api/devices -H "Authorization: Bearer $TOKEN"

# 新增设备
curl -s -X POST http://localhost/api/devices -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"UAV-099","deviceType":"UAV","name":"冒烟测试机","area":"测试区"}'

# 检索(验证限流: 快速连发 30 次应出现 429)
curl -s -X POST http://localhost/api/search/events -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"page":1,"size":5}'

# 上传图片
curl -s -X POST http://localhost/api/files -H "Authorization: Bearer $TOKEN" \
  -F "file=@test.jpg" -F "deviceId=UAV-001"
```
